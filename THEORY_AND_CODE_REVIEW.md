# Теория, логика кода и проверка ТЗ

Документ описывает Android-приложение чата из проекта `FV3Chat`: из чего оно состоит, как запускается, как работает с сервером, как устроены экраны и насколько реализация соответствует техническому заданию.

## 1. Общая теория проекта

Приложение написано на Kotlin под Android и использует Jetpack Compose вместо XML-разметки экранов. Это значит, что интерфейс описан функциями `@Composable`, а внешний вид зависит от текущего состояния приложения.

Основные технологии:

- `Kotlin` - основной язык проекта.
- `Jetpack Compose` - декларативный UI.
- `Material 3` - готовые компоненты интерфейса: кнопки, поля ввода, карточки, диалоги.
- `ViewModel` - хранит состояние экрана и переживает поворот устройства.
- `StateFlow` - поток состояния, на который подписывается UI.
- `Coroutines` - асинхронные сетевые операции без блокировки главного потока.
- `Retrofit` - описание HTTP API сервера через Kotlin-интерфейс.
- `OkHttp` - HTTP-клиент и interceptor для добавления токена авторизации.
- `Moshi` - преобразование JSON в Kotlin-модели и обратно.
- `Coil` - загрузка картинок по URL в Compose.
- `SharedPreferences` - простое сохранение логина и пароля на устройстве.

Архитектура проекта разделена на слои:

- `MainActivity` - точка входа Android-приложения.
- `ui` - экраны, состояние интерфейса и ViewModel.
- `data/network` - Retrofit API, сетевой модуль, сессия авторизации.
- `data/repository` - слой, который прячет детали HTTP-запросов от UI.
- `data/model` - DTO-модели сервера и доменная модель сообщения.
- `data/storage` - сохранение логина и пароля.
- `res/values` - строки и стили приложения.

Главная идея: UI ничего не знает о конкретных HTTP-запросах. UI вызывает методы `ChatViewModel`, ViewModel обращается к `ChatRepository`, репозиторий вызывает `ChatApi`, а `ChatApi` через Retrofit выполняет реальные запросы к серверу.

## 2. Как запустить приложение в Android Studio

1. Открыть Android Studio.
2. Нажать `File -> Open`.
3. Выбрать папку проекта `FV3`, то есть корневую папку, где лежат `settings.gradle.kts`, `build.gradle.kts` и папка `app`.
4. Дождаться Gradle Sync. Android Studio должна скачать зависимости: Compose, Retrofit, Moshi, Coil.
5. Проверить, что установлен JDK 17. В проекте указано:
   - `kotlin.jvmToolchain(17)`;
   - Android Gradle Plugin `8.7.3`;
   - Kotlin `2.0.21`.
6. Выбрать устройство:
   - физический Android-телефон с включённой отладкой по USB;
   - или эмулятор через `Device Manager`.
7. Вверху выбрать конфигурацию `app`.
8. Нажать зелёную кнопку `Run`.
9. При первом запуске приложение откроет экран входа.
10. Ввести логин и пароль от сервера.
11. После успешного входа откроется список каналов.

Если сборка не стартует:

- проверить интернет для загрузки Gradle-зависимостей;
- выполнить `File -> Sync Project with Gradle Files`;
- убедиться, что `compileSdk = 35` доступен в Android SDK Manager;
- проверить, что пакет не начинается с `com.example` - в проекте используется `ru.bippbupp.fv3chat`, это нормально по ТЗ.

## 3. Структура файлов

`app/src/main/AndroidManifest.xml`

- объявляет разрешение на интернет;
- регистрирует `MainActivity`;
- не блокирует поворот экрана.

`app/build.gradle.kts`

- подключает Android, Kotlin и Compose;
- задаёт `namespace` и `applicationId`;
- включает Compose;
- добавляет зависимости для UI, lifecycle, сети и картинок.

`MainActivity.kt`

- запускает Compose UI;
- создаёт `ChatViewModel`;
- определяет ориентацию экрана;
- передаёт состояние и обработчики событий в `ChatApp`;
- перехватывает кнопку/жест назад.

`ChatApp.kt`

- содержит все Compose-экраны;
- выбирает, какой экран показать: вход, список чатов, сообщения, картинку;
- отдельно обрабатывает портретный и ландшафтный режим.

`ChatViewModel.kt`

- хранит состояние приложения;
- выполняет вход, выход, загрузку каналов, загрузку сообщений, отправку сообщений;
- обрабатывает ошибки;
- решает, что делать при нажатии назад.

`ChatUiState.kt`

- описывает всё состояние интерфейса одной immutable `data class`.

`ChatApi.kt`

- описывает API сервера через Retrofit-аннотации.

`NetworkModule.kt`

- создаёт Retrofit-клиент;
- добавляет токен в заголовок `X-Auth-Token`;
- строит URL для превью и полной картинки.

`ChatRepository.kt`

- вызывает API;
- проверяет HTTP-ошибки;
- преобразует DTO в удобные модели;
- отделяет сетевые ошибки от ошибок авторизации.

`ChatModels.kt`

- описывает формат логина, сообщений, текста и картинок.

`CredentialsStore.kt`

- сохраняет и читает логин/пароль из `SharedPreferences`;
- позволяет пропускать экран входа при повторном запуске.

- очищает поле ввода;
- выключает `isSending`.

Строки 162-175: `handleBack()`.

- если открыта картинка, закрывает картинку;
- иначе если открыт чат, закрывает чат;

Строки 177-213: приватный `login(...)`.

- проверяет пустые логин/пароль;
- показывает понятную ошибку, если поля пустые;
- включает состояние загрузки;
- вызывает `repository.login(...)`;
- сохраняет credentials;
- помечает пользователя авторизованным;
- запускает загрузку каналов;
- при ошибке передаёт её в `handleFailure`.

Строки 215-229: `loadChannels()`.

- включает загрузку списка чатов;
- вызывает `/channels`;
- записывает каналы в состояние;
- выключает загрузку.

Строки 231-246: `loadMessages(channel)`.

- включает загрузку сообщений;
- запрашивает первую страницу сообщений;
- сортирует и сохраняет сообщения по имени канала;
- выставляет `canLoadMore`, если пришло ровно 20 сообщений.

Строки 248-287: `handleFailure(...)`.

- преобразует технические исключения в понятные строки;
- `InvalidCredentialsException` становится `Неверный логин или пароль`;
- `AuthExpiredException` становится `Сессия истекла. Войдите заново`;
- сетевые ошибки становятся `Не удалось связаться с сервером`;
- серверные ошибки становятся `Сервер вернул ошибку`;
- при 401 после входа очищает credentials, сбрасывает токен и возвращает пользователя на экран входа.

Строка 289: `text(id)` берёт строку из ресурсов.

Строки 292-296: `withMergedMessages(...)` объединяет старые и новые сообщения, удаляет дубли по `id`, сортирует.

Строки 298-299: `sortedById()` сортирует сообщения по числовому `id`; если id не число, сообщение уходит в конец.

## 5. Логика экранов

### Экран входа

Показывается, когда `state.isLoggedIn == false`.

Пользователь вводит логин и пароль. Кнопка входа вызывает `viewModel.loginFromInput()`. ViewModel проверяет пустые поля, вызывает `repository.login(...)`, получает токен и сохраняет его в `AuthSession`. После успеха `isLoggedIn` становится `true`, экран входа исчезает, начинается загрузка каналов.

Если логин/пароль неверные, сервер возвращает 401. Репозиторий превращает это в `InvalidCredentialsException`, ViewModel превращает в строку `Неверный логин или пароль`, UI показывает `AlertDialog`.

Если логин и пароль были сохранены ранее, `ChatViewModel.init` запускает автоматический вход, поэтому экран входа фактически пропускается.

### Экран чатов в портретном режиме

Показывается, когда пользователь авторизован, ориентация portrait и `selectedChat == null`.

Экран выводит список каналов из `/channels`. Нажатие на канал вызывает `openChat(channel)`. Если сообщения ещё не загружались, ViewModel вызывает загрузку первой страницы. Кнопка `Выйти` вызывает `logout()`, очищает credentials и возвращает к экрану входа.

### Экран сообщений в портретном режиме

Показывается, когда выбран чат.

Сверху есть кнопка `К чатам`, которая вызывает `closeChat()`. Основная часть - `MessageList`. Внизу - поле ввода и кнопка отправки.

Текстовые сообщения показываются обычным `Text`. Картинки показываются через `/thumb/`. По клику на картинку открывается полноэкранный экран картинки.

Пагинация сделана кнопкой `Загрузить ещё`. Она запрашивает не больше 20 сообщений за раз.

### Экран картинки

Это overlay поверх текущего экрана. Если `fullImagePath != null`, `ChatApp` показывает `FullImageScreen`. Полная картинка грузится из `/img/`. Кнопка `Закрыть картинку` очищает `fullImagePath` и возвращает пользователя к чату.

### Ландшафтный режим

Если ориентация landscape, `ChatApp` всегда выбирает `LandscapeChatScreen`.

Слева находится список чатов. Справа:

- если чат не выбран, надпись `Выберите чат`;
- если чат выбран, экран сообщений.

Открытый чат подсвечивается в списке через `ChannelRow(selected = true)`.

## 6. Логика работы с сервером

### Базовый адрес

Все запросы идут на:

```text
https://faerytea.name/
```

### Авторизация

1. Пользователь вводит логин и пароль.
2. ViewModel вызывает `ChatRepository.login(name, password)`.
3. Репозиторий отправляет:

```text
POST /login
Body: { "name": "...", "pwd": "..." }
```

4. Если ответ 401, показывается ошибка `Неверный логин или пароль`.
5. Если ответ успешный, тело ответа читается как токен.
6. Токен сохраняется в `AuthSession.token`.
7. OkHttp interceptor начинает добавлять его в каждый следующий запрос:

```text
X-Auth-Token: <token>
```

### Загрузка каналов

После входа ViewModel вызывает `loadChannels()`.

Репозиторий выполняет:

```text
GET /channels
```

Ответ - список строк. Репозиторий сортирует каналы, ViewModel кладёт их в `state.channels`, UI показывает список.

### Загрузка сообщений

При открытии чата ViewModel вызывает `loadMessages(channel)`.

Репозиторий выполняет:

```text
GET /channel/{name}?limit=20&lastKnownId=0&reverse=false
```

Сервер возвращает список сообщений. Каждое сообщение преобразуется из `MessageDto` в `ChatMessage`. UI показывает текст и/или картинку.

### Пагинация

Когда пользователь нажимает `Загрузить ещё`, ViewModel берёт id самого старого уже загруженного сообщения и выполняет:

```text
GET /channel/{name}?limit=20&lastKnownId=<oldestId>&reverse=true
```

Пришедшие сообщения объединяются с текущими, дубли удаляются по `id`, итог сортируется по `id`.

### Отправка сообщения

Когда пользователь вводит непустой текст и нажимает `Отправить`, ViewModel вызывает `repository.sendText(...)`.

Репозиторий выполняет:

```text
POST /messages
Body:
{
  "from": "<username>",
  "to": "<channel>",
  "data": {
    "Text": {
      "text": "<message>"
    }
  }
}
```

После успешного ответа ViewModel добавляет отправленное сообщение в локальный список, чтобы пользователь сразу увидел его в чате.

### Загрузка картинок

Для превью используется:

```text
GET /thumb/<imagePath>
```

Для полной картинки:

```text
GET /img/<imagePath>
```

Фактическую загрузку делает Coil через `AsyncImage`.

### Logout

При выходе:

```text
POST /logout
```

Даже если серверный logout завершится ошибкой, приложение очищает локальный токен и сохранённые логин/пароль.

### Обработка 401

Есть два разных сценария:

- 401 при `/login` - это неверный логин/пароль.
- 401 при других запросах - сессия истекла или токен недействителен.

Во втором случае приложение:

- очищает `SharedPreferences`;
- сбрасывает `AuthSession.token`;
- создаёт новый `ChatUiState`;
- возвращает пользователя на экран входа;
- показывает сообщение `Сессия истекла. Войдите заново`.

1. В проекте нет автоматических тестов. Для учебного задания это может быть допустимо, но для надёжности можно добавить хотя бы unit-тесты на `ChatRepository` и `ChatViewModel`.
